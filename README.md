# سالاری‌اپ — سامانه حسابداری، انبار و اقساط لوازم خانگی و آشپزخانه

اپلیکیشن **کاملاً آفلاین و نصب‌شدنی روی اندروید** برای فروشگاه‌های لوازم خانگی و آشپزخانه.
همه داده‌ها روی حافظهٔ خود گوشی (IndexedDB) ذخیره می‌شود؛ هیچ سروری لازم نیست و اطلاعات شما جایی ارسال نمی‌شود.

> رابط کاربری فارسی، راست‌به‌چپ، تاریخ شمسی و ارقام فارسی — بهینه برای موبایل و تبلت، بدون شکستن کلمات و بدون دو خطه شدن برچسب‌ها.

## ۱) اجرا و نصب

```bash
npm install
npm run dev        # اجرای نسخه توسعه روی http://localhost:5173
npm run build      # ساخت نسخه نهایی در پوشه dist
npm run preview    # پیش‌نمایش نسخه ساخته‌شده روی پورت 4173
npm test           # اجرای تست‌ها (۵۹ تست)
```

### نصب روی گوشی اندروید (PWA)
1. `npm run build` را اجرا کنید و پوشهٔ `dist` را روی یک هاست HTTPS قرار دهید (هر هاست سادهٔ استاتیک کافی است).
2. در کروم اندروید آدرس را باز کنید → منوی سه‌نقطه → **افزودن به صفحه اصلی / نصب برنامه**.
3. آیکون اپ روی صفحه اصلی ساخته می‌شود و بدون اینترنت هم باز می‌شود.

> **چرا HTTPS؟** Service Worker، اعلان سیستمی و همگام‌سازی پس‌زمینه فقط روی HTTPS (یا localhost) فعال می‌شوند.

### نصب نسخه اندروید (APK)
APK آماده در بخش **Releases** همین مخزن منتشر می‌شود:
`https://github.com/hammrahnet-afk/salariapp/releases/latest`

۱. فایل `salariapp-x.y.z.apk` را دانلود کنید.
۲. اگر اندروید اجازه نداد، برای مرورگر یا مدیر فایل «نصب برنامه از منابع ناشناس» را روشن کنید.
۳. نصب کنید و آیکون «سالاری‌اپ» را باز کنید.

ساخت نسخه جدید به‌صورت خودکار با GitHub Actions (فایل `.github/workflows/android.yml`) انجام می‌شود:
انتشار یک تگ `v1.0.1` → تست‌ها، ساخت وب، همگام‌سازی Capacitor، ساخت APK امضاشده و انتشار در Releases.

### ساخت محلی APK (اختیاری)
اگر Android Studio دارید:

```bash
npm run build && npx cap sync android
npx cap open android     # سپس Build > Generate Signed Bundle / APK
```

کلید امضای پروژه در `android/app/salari-release.p12` نگه‌داری می‌شود
(رمز و نام مستعار پیش‌فرض: `salari1404` / `salari`، قابل تغییر با متغیرهای محیطی
`SALARI_STORE_PASSWORD`، `SALARI_KEY_PASSWORD`، `SALARI_KEY_ALIAS`).
دلیل وجود آن این است که نسخه‌های بعدی روی نسخه نصب‌شده **به‌روزرسانی** شوند و داده‌های شما پاک نشود.

### اعلان بومی سررسید در نسخه اندروید
علاوه بر موتور داخلی، اپ اندروید سررسید اقساط را با `AlarmManager` سیستم‌عامل زمان‌بندی می‌کند؛
یعنی اعلان «سررسید قسط امروز» حتی وقتی برنامه بسته است هم نمایش داده می‌شود.

### مجوزهای اندروید (درخواست خودکار در اولین اجرا)
در نسخه ۱٫۰٫۱ به بعد، اپ هنگام **اولین باز شدن** پنجره «اجازه‌های لازم برای سالاری‌اپ» را نشان می‌دهد و
اجازه‌های زیر را مستقیم از خود برنامه درخواست می‌کند (بدون نیاز به رفتن به تنظیمات گوشی):

| مجوز | چرا لازم است | نحوه درخواست |
| --- | --- | --- |
| `POST_NOTIFICATIONS` | نمایش اعلان سررسید (اندروید ۱۳+) | پنجره سیستمی اندروید با دکمه «درخواست اجازه اعلان» |
| آلارم و یادآور دقیق (`SCHEDULE_EXACT_ALARM`) | اجرای یادآوری در ساعت دقیق تعیین‌شده (اندروید ۱۲+) | دکمه «باز کردن تنظیمات آلارم» → صفحه سیستمی |
| معافیت از بهینه‌سازی باتری | جلوگیری از تأخیر اعلان‌ها در حالت خواب گوشی | دکمه «حذف محدودیت باتری» |

کانال اعلان `salari-due` (اهمیت بالا، صدا + ویبره) در همان اجرا ساخته می‌شود تا در تنظیمات سیستم دیده شود.
هر زمان خواستید، وضعیت این مجوزها با «تنظیمات → مجوزهای اندروید» بررسی و دوباره درخواست می‌شود
(منبع کد: `src/components/Permissions.tsx` و `src/lib/native.ts`).

## ۳) منطق حساب‌داری (مهم)

این بخش را بخوانید تا اعداد همیشه درست بمانند:

- **ماندهٔ هر مشتری** = `مانده از قبل` + مجموع `باقی‌ماندهٔ فاکتورها` − `مجموع واریزی‌ها`.
- **قسط‌بندی بدهی جدید نمی‌سازد.** قرارداد اقساط فقط یک «زمان‌بندی» برای بدهی موجود است؛
  به همین دلیل وقتی فاکتور نسیه ثبت می‌شود، بدهی همان‌جا به حساب مشتری اضافه می‌شود و
  قسط‌بندی فقط سررسیدها را می‌شکند. (جلوگیری از دوباره‌شماری بدهی)
- **هر واریزی** از بدهی کل کم می‌شود و به‌صورت خودکار روی **قدیمی‌ترین قسط باز** (FIFO) تخصیص می‌یابد؛
  می‌توانید قسط مقصد را هم دستی انتخاب کنید.
- **حذف فاکتور** موجودی کالاها را به انبار برمی‌گرداند و سند انبار مرتبط را پاک می‌کند.
- **فروش مشتری روزگذر** به حساب هیچ مشتری ثبت‌شده‌ای اضافه نمی‌شود و همان‌جا نقدی تسویه می‌شود.
- **گرد کردن اقساط**: باقی‌ماندهٔ تقسیم روی قسط آخر گذاشته می‌شود تا جمع اقساط دقیقاً برابر مبلغ قرارداد باشد.

## ۴) اقساط و پیامک یادآوری

### حالت دستی (پیش‌فرض، بدون هزینه)
در روز سررسید، پیامک در «مرکز پیامک» **صف** می‌شود و با یک لمس، اپ پیامک گوشی با شماره و متن آماده باز می‌شود.
مناسب زمانی که پنل پیامکی ندارید.

### حالت خودکار (پنل پیامکی)
در «تنظیمات → پیامک» حالت را روی **خودکار** بگذارید و یکی از پنل‌ها را تنظیم کنید:

| پنل | مقادیر لازم |
|---|---|
| کاوه‌نگار | کلید API + (اختیاری) شمارهٔ فرستنده |
| ملی‌پیامک | نام کاربری، رمز عبور، شمارهٔ فرستنده |

سپس «ارسال خودکار در روز سررسید» را روشن کنید و ساعت ارسال را انتخاب کنید.

> **نکتهٔ فنی CORS:** اگر پنل شما هدر CORS برنگرداند، مرورگر اجازهٔ ارسال مستقیم نمی‌دهد و در لاگ پیامک
> خطای «ارتباط با پنل برقرار نشد» ثبت می‌شود. در این حالت یا از حالت دستی استفاده کنید یا یک رلهٔ ساده
> روی سرور خود بسازید که درخواست را به پنل پاس بدهد.

قالب پیامک‌ها در تنظیمات قابل ویرایش است و این متغیرها را پشتیبانی می‌کند:
`{name} {amount} {unit} {due} {idx} {count} {debt} {late} {shop} {phone} {date}`

### «همیشه در حال اجرا بودن» — برنامه در پس‌زمینه
سه لایه پیاده‌سازی شده است:

1. **موتور داخلی (هر ۶۰ ثانیه):** تا وقتی اپ باز است (حتی در تب پشت‌زمینه) اقساط را بررسی می‌کند.
2. **Periodic Background Sync:** کروم اندروید، پس از **نصب** اپ، موتور را حتی وقتی اپ بسته است
   (حداقل هر ۱۵ دقیقه، بسته به تصمیم سیستم‌عامل) اجرا می‌کند. نیازمند نصب PWA + اجازهٔ همگام‌سازی پس‌زمینه.
3. **Wake Lock اختیاری:** با روشن کردن «حالت همیشه‌روشن» در تنظیمات، صفحه خاموش نمی‌شود تا برنامه
   در جریان بماند (مصرف باتری بیشتر).

> واقعیت فنی: هیچ وب‌اپ یا PWA نمی‌تواند تضمین کند که سیستم‌عامل اندروید هرگز آن را از حافظه بیرون نکند.
> برای ارسال ۱۰۰٪ تضمین‌شده در ساعت مشخص — حتی وقتی گوشی خاموش/قفل است — به یک سرویس سرور (Cron) نیاز است.
> راهکار وب‌اپ این است که در اولین فرصت (باز شدن اپ، اجرای پس‌زمینه، آنلاین شدن) عقب‌افتادگی را جبران کند؛
> همین کار را موتور انجام می‌دهد و اقساط ارسال‌نشده را در اولین اجرا می‌فرستد.
> برای بازه‌های طولانی‌مدت (مثلاً ۳۰ روز بدون باز کردن اپ)، می‌توانید در «تنظیمات → پیامک» فاصلهٔ ارسال را
> روی حالت دستی بگذارید تا هیچ پیامی از دست نرود.

## ۵) پشتیبان‌گیری

- **خودکار:** هر ۱ تا ۳۰ روز (قابل تنظیم)، نسخه‌ای در خود دستگاه ساخته و نسخه‌های قدیمی پاک می‌شوند.
- **دستی:** ساخت فایل JSON + دانلود فوری، و بازیابی از فایل.
- **گوگل‌درایو (اختیاری):** برای فعال‌سازی، در Google Cloud Console یک OAuth Client ID از نوع
  «Web application» بسازید، مبدأ اپ را در *Authorized JavaScript origins* اضافه کنید و شناسه را در
  «تنظیمات → اتصال گوگل‌درایو» وارد کنید.

> پشتیبان حاوی تمام کالاها، مشتریان، فاکتورها، اقساط، پیامک‌ها و تنظیمات است. آن را در جای امن نگه دارید.

## ۷) تست

```bash
npm test
```

## ۸) نکات نگهداری

- داده‌ها در مرورگر ذخیره می‌شوند؛ **پاک کردن داده‌های سایت در مرورگر = حذف کل اطلاعات**. پشتیبان بگیرید.
- برای انتقال اطلاعات به گوشی دیگر: پشتیبان دستی بگیرید و در دستگاه جدید «بازیابی از فایل» بزنید.
- اگر نام فروشگاه، شماره تماس یا قالب پیامک را تغییر دادید، همهٔ پیامک‌های بعدی به‌روز می‌شوند.
